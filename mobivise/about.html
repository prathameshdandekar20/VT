About Mobivise

An intelligent, transparent smartphone purchasing decision-support system built with pure HTML5, CSS3, Vanilla JavaScript, and JSON. 100% framework-free.

1. Project Overview & Problem Statement

Consumers frequently struggle with specification overload when shopping for smartphones. Complex marketing metrics (fabrication nanometers, megapixel counts, peak brightness nits) obscure whether a device actually meets daily user requirements. Commercial retail sites exacerbate this with sponsored ads and undisclosed affiliate promotions.

Mobivise provides an unbiased, mathematically grounded recommendation guide. It filters by hard budget constraints, normalizes multi-attribute hardware metrics, and applies dynamic weightings to deliver clear match percentages and honest trade-offs.

2. Mathematical Recommendation Algorithm (MAUT)

Mobivise utilizes Multi-Attribute Utility Theory (MAUT). Rather than arbitrary random scoring or black-box machine learning models, each eligible smartphone undergoes an interpretable three-stage mathematical pipeline:

Stage 1: Metric Normalization

Raw metrics with disparate dimensions (AnTuTu score ~2,200,000 vs RAM ~16GB) are normalized to a uniform scale $S_i \in [0, 100]$:

Norm(x) = Math.min(100, Math.max(0, ((x - min) / (max - min)) * 100))

Stage 2: Dynamic Priority Weights ($W_i$)

Stage 3: Composite Utility Match Score

Match% = Σ (W_i × S_i) + BrandBonus [Capped at 99%]

3. Relational Database Schema (3NF)

The dataset satisfies Third Normal Form (3NF) without data redundancy, mapped directly to client-side JSON collections:

brands

id (PK), brand_name, slug, logo, website, description

smartphones

id (PK), brand_id (FK), model_name, slug, current_price, is_5g, popularity

specifications

id (PK), smartphone_id (FK), processor, ram, storage, display, camera, battery

prices

id (PK), smartphone_id (FK), retailer_name, price, retailer_url, checked_at

4. Econometric Value-for-Money (VFM) & Decision Science

To counter arbitrary marketing pricing, Mobivise implements an econometric Value-for-Money (VFM) Index. Drawing from marginal utility theory, price is modeled with square-root diminishing returns:

HardwareScore = 0.45 × Norm(AnTuTu) + 0.25 × Norm(Battery) + 0.15 × Norm(RAM) + 0.15 × Norm(Camera)
RawRatio = HardwareScore / √(Price / 10,000)
VFM Index (0 – 100) = round(50 + 48 × (RawRatio − MinRatio) / (MaxRatio − MinRatio))

In the Price vs. Performance Matrix (Chart.js Bubble Plot on Explorer), smartphones positioned in the upper-left quadrant represent Pareto-optimal sweet spots delivering maximum raw computational throughput per rupee invested.

5. Viva Voce Technical Defense Notes

Q1: Why is there no user registration or login?

Mobivise is an open consumer decision guide. Requiring authentication introduces user friction. Comparison states are managed purely in the browser using localStorage, guaranteeing privacy, zero database session load, and offline responsiveness.

Q2: Why use MAUT instead of Machine Learning (e.g., collaborative filtering)?

Collaborative filtering suffers from the cold-start problem (new phones have no user interaction data) and acts as an unexplainable black box. MAUT delivers mathematically transparent, explainable recommendations where every score component is accountable and deterministic.

Q3: What are the performance benefits of a client-side static web application?

Zero backend latency: queries, filters, and comparisons execute in less than 1 millisecond directly in browser memory without database locks or server strain. The application can run offline or directly via file:/// protocol.
